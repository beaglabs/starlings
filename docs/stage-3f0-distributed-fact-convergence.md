# Stage 3F.0 — Distributed Fact Convergence

Stage 3F.0 is the first Starlings experiment that scores **collective outcome**
instead of requiring a canonical interaction trajectory.

Its question is:

> Can locally informed model-backed operators recover a correct global state
> through self-chosen Starlings interactions, and does CFG-constrained decoding
> improve protocol control without suppressing successful coordination?

This is a controlled-emergence experiment. It deliberately removes the
Stage 3E workflow classifier from the outcome definition.

## Environment

Five workers are arranged in a static ring:

\`\`\`text
W1 — W2 — W3 — W4 — W5
|                   |
└───────────────────┘
\`\`\`

There are five facts: \`A,B,C,D,E\`.

For seed 0, private knowledge is:

\`\`\`text
W1: A,B
W2: B,C
W3: C,D
W4: D,E
W5: E,A
\`\`\`

The assignment rotates by \`seed % 5\`, so seeds 0–4 cover every rotation of
the same overlapping-information structure.

Worker 1 is the deterministic collector. A run succeeds when:

\`\`\`text
Worker 1 knowledge == {A,B,C,D,E}
\`\`\`

The first smoke experiment uses:

- 5 workers;
- 5 facts;
- overlapping private knowledge;
- ring-only neighborhoods;
- synchronous rounds;
- one model-selected interaction per worker per round;
- at most 10 rounds;
- no worker failure;
- no message loss;
- no false initial information.

Those harder conditions belong to later Stage 3F experiments.

## Autonomous interaction language

The model is not told which interaction to choose.

It receives its identity, two ring neighbors, original private facts, current
knowledge, the current round, and the collective objective. It must choose
exactly one of:

\`\`\`text
CLAIM <facts>
QUERY EVIDENCE <fact>
\`\`\`

Examples:

\`\`\`text
CLAIM A,C
QUERY EVIDENCE D
\`\`\`

\`CLAIM\` broadcasts the claimed fact mask to both ring neighbors. A worker may
only claim facts already present in its current knowledge; claiming an unknown
fact is a semantic violation and has no effect.

\`QUERY EVIDENCE\` queries both ring neighbors for one fact. A neighbor that
knows the requested fact returns deterministic evidence, which updates the
querying worker's knowledge.

The LLM chooses the interaction and payload. Zig owns the state transition
semantics.

## Synchronous rounds

All five model calls in a round see the same pre-round snapshot.

Their interactions are applied only after all five calls complete. This avoids
worker-order effects in the state visible to the model.

Each raw record includes:

\`\`\`text
run_seed
mode
round
worker
knowledge_before
generation_seed
completion_tokens
latency_us
completion
\`\`\`

The Zig replayer independently reconstructs the state and rejects records when
\`knowledge_before\` or \`generation_seed\` disagrees with deterministic
replay.

## Paired A/B treatment

For each run seed there are two closed-loop population runs:

\`\`\`text
typed_unconstrained
vs
cfg_constrained
\`\`\`

Both use the same:

- model;
- initial fact placement;
- topology;
- prompt rules;
- per-worker generation seed;
- sampler settings;
- 32-token output budget;
- \`reasoning_effort: "none"\`;
- \`enable_thinking: false\`;
- maximum rounds.

The constrained mode alone adds:

\`\`\`json
"grammar": "<contents of grammars/stage3f0.gbnf>"
\`\`\`

After the treatment causes different actions, later prompts may legitimately
differ because each closed-loop population has reached a different state.
That divergence is part of the treatment effect.

## Grammar

\`grammars/stage3f0.gbnf\` constrains only the factual interaction syntax:

\`\`\`text
root ::= interaction
interaction ::= claim | query-evidence
claim ::= "CLAIM " fact-list
query-evidence ::= "QUERY EVIDENCE " fact
fact-list ::= fact | fact "," fact-list
fact ::= "A" | "B" | "C" | "D" | "E"
\`\`\`

A grammatically valid claim can still be semantically invalid if it asserts a
fact the sender does not know. CFG controls syntax; the deterministic runtime
controls semantic state invariants.

## Metrics

The primary outcome is:

\`\`\`text
collective success
\`\`\`

The replay summary also reports:

- protocol-valid model actions;
- invalid model actions;
- backend failures;
- semantic violations;
- rounds to termination;
- logical network messages;
- useful fact deliveries;
- duplicate fact transmissions;
- useful facts per network message;
- model completion tokens;
- generated bytes;
- model latency;
- number of unique successful trajectory hashes.

A successful trajectory is not required to match any predefined conversation.

Two different interaction sequences that both make Worker 1 recover the full
fact set are both successes.

## Why trajectory diversity matters

Stage 3F.0 is looking for:

\`\`\`text
bounded protocol rules
        +
different locally chosen trajectories
        +
same correct global outcome
\`\`\`

If successful runs occur through multiple trajectory hashes, that is evidence
that the system is not merely replaying one scripted workflow.

Trajectory diversity alone does not prove useful emergence; it is interpreted
alongside collective success and communication efficiency.

## Start llama.cpp

For the current Gemma 4 E2B test model:

\`\`\`sh
llama-server \
  -m ./models/gemma-4-E2B-it-Q4_K_M.gguf \
  --port 8080 \
  -np 1 \
  -c 4096
\`\`\`

## Validate the runner

\`\`\`sh
python3 tools/stage3f0_llama_cpp.py --self-test
python3 tools/stage3f0_llama_cpp.py --dry-run
\`\`\`

The default five-seed smoke has a maximum of:

\`\`\`text
5 seeds × 2 modes × 10 rounds × 5 workers = 500 model generations
\`\`\`

Runs terminate immediately when Worker 1 reaches the complete fact set, so
the actual generation count can be lower.

## Run the first smoke experiment

Use a fresh result path:

\`\`\`sh
python3 tools/stage3f0_llama_cpp.py \
  --base-url http://127.0.0.1:8080 \
  --seeds 5 \
  --output trials/stage3f0-gemma4-e2b-smoke.tsv
\`\`\`

Stage 3F.0 intentionally does not support resume in v1. Closed-loop prompts
depend on prior generated actions, so an interrupted smoke run should be
restarted rather than partially reconstructed by the transport layer.

## Summarize and replay in Zig

\`\`\`sh
zig run src/stage3f0_summary.zig -- \
  trials/stage3f0-gemma4-e2b-smoke.tsv
\`\`\`

The summary refuses to treat malformed, unreplayable, or unbalanced run sets
as experimental evidence.

## First gate

The first smoke is not a CFG promotion test.

The Stage 3F.0 gate is:

> At least one autonomous population can solve the distributed-information
> task, and successful runs can occur without requiring a canonical interaction
> trajectory.

If the harness behaves correctly, the next step is a larger seed set and then
harder environments:

\`\`\`text
3F.1 overlapping-knowledge efficiency
3F.2 incorrect claim + challenge/retraction
3F.3 specialist knowledge + delegation
3F.4 worker/message failure
3F.5 bounded/dynamic neighborhoods
\`\`\`

CFG becomes promotable only if constrained communication preserves collective
success while materially improving protocol reliability or communication
efficiency across these controlled-emergence tasks.
